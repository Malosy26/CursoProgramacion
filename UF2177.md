## Diferencia entre `extends` e `implements` en Java

En Java, tanto `extends` como `implements` se utilizan para la herencia y la implementación de funcionalidades, pero tienen propósitos diferentes. A continuación, te explico cuándo usar cada uno.

### 1. **`extends`**

La palabra clave `extends` se usa cuando una **clase** hereda de otra **clase**.  
Es un mecanismo de **herencia** en el cual la clase hija **hereda atributos y métodos** de la clase padre.

#### **¿Cuándo usar `extends`?**
- Se usa cuando quieres que una clase hija herede de una clase base o padre.
- La clase hija puede acceder a los métodos y atributos de la clase padre.
- **Solo se puede extender una clase** (Java no soporta la herencia múltiple de clases).

#### **Ejemplo:**
```java
public class Vehiculo {
    protected String matricula;
    protected int deposito;

    public void repostar(int cantidad) {
        deposito += cantidad;
    }
}

public class Coche extends Vehiculo {
    private int numeroPuertas;

    public void abrirMaletero() {
        System.out.println("Maletero abierto");
    }
}


# Modificadores de Acceso en Java

En Java, los modificadores de acceso determinan la **visibilidad** de clases, métodos, variables y constructores. Los principales son:

| Modificador  | Clase | Paquete | Subclase | Mundo (todos) |
|--------------|:-----:|:-------:|:--------:|:-------------:|
| `public`     |  ✅   |   ✅    |   ✅     |      ✅       |
| `protected`  |  ✅   |   ✅    |   ✅     |      ❌       |
| *(default)*  |  ✅   |   ✅    |   ❌     |      ❌       |
| `private`    |  ✅   |   ❌    |   ❌     |      ❌       |

## 📚 Guía Rápida de JavaDocs

**JavaDoc** es una herramienta que permite generar documentación en HTML a partir de comentarios especiales en el código Java. Estos comentarios deben comenzar con `/**` y se colocan justo encima de clases, métodos, interfaces o atributos.

---

## ✏️ Estructura Básica

/**
 * Breve descripción de la clase o método.
 *
 * Descripción más detallada si es necesario.
 *
 * @etiqueta Descripción de la etiqueta
 */


# 🧾 Tabla de etiquetas JavaDoc y anotaciones comunes en clases y métodos

## 📌 Etiquetas de JavaDoc

| Etiqueta               | Uso / Descripción                                                                            |
|------------------------|---------------------------------------------------------------------------------------------|
| `@author`              | Nombre del autor del código.                                                                |
| `@version`             | Versión de la clase o API.                                                                  |
| `@param`               | Describe un parámetro en un método o constructor.                                           |
| `@return`              | Describe el valor devuelto por un método.                                                  |
| `@throws` / `@exception` | Explica qué excepción puede lanzar un método.                                           |
| `@see`                 | Añade una referencia a otra clase, método o documentación relacionada.                     |
| `@since`               | Indica desde qué versión del código está disponible el elemento documentado.               |
| `@deprecated`          | Indica que una clase, método o campo está obsoleto.                                         |
| `@serial`              | Describe elementos serializables en una clase que implementa `Serializable`.               |
| `@inheritDoc`          | Hereda la documentación de una superclase o interfaz.                                       |
| `@link`                | Inserta un enlace en línea a otro elemento de código (formato: `{@link Clase#método}`).     |
| `@code`                | Muestra texto en monoespaciado como si fuera código: `{@code ejemplo}`.                    |
| `@literal`             | Escapa caracteres especiales como `<`, `>` en el texto JavaDoc.                            |

---

## 🛠️ Anotaciones Java comunes (NO son JavaDoc pero se usan mucho)

| Anotación              | Uso / Descripción                                                                            |
|------------------------|---------------------------------------------------------------------------------------------|
| `@Override`            | Indica que un método sobrescribe a uno de una superclase o interfaz.                        |
| `@Deprecated`          | Marca elementos como obsoletos. Se recomienda usar `@deprecated` en JavaDoc también.        |
| `@SuppressWarnings`    | Suprime advertencias del compilador.                                                        |
| `@FunctionalInterface` | Marca una interfaz con un solo método abstracto (para usarla con lambdas).                 |
| `@SafeVarargs`         | Evita advertencias con varargs genéricos en métodos `final`, `static` o constructores.     |
| `@Documented`          | Indica que la anotación debe incluirse en el JavaDoc generado.                             |
| `@Retention`           | Especifica si la anotación se guarda en tiempo de compilación, clase o ejecución.          |
| `@Target`              | Indica en qué elementos se puede aplicar una anotación (métodos, campos, clases, etc.).    |

---

🔍 **Nota:**  
- Las etiquetas **JavaDoc** se usan dentro de comentarios `/** ... */`.
- Las **anotaciones** se usan directamente sobre el elemento del código (`@Override`, `@Deprecated`, etc.).
